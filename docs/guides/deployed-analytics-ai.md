# Deployed walkthrough: analytics and AI

Allow 10-15 minutes to show retail and analytics teams the ontology, Data
Agents, and Power BI report over synthetic data. Start with the
[walkthrough overview](deployed-walkthrough.md).

!!! note "Optional surfaces"

    Ontology and Data Agents require valid source bindings,
    permissions, and capability support. Skip a feature that has not passed
    its preflight checks.

## 1. Show business context in the ontology

An ontology is a business map that connects concepts such as Store, Product,
Customer, and Receipt to the underlying data. Show this section only after
deployment confirmed that the ontology exists and points to the intended
Lakehouse and Eventhouse sources.

1. Open the **Ontologies** folder.
2. Open **RetailOntology_AutoGen**.
3. Select the `Store` entity type in **Explorer**.
4. Select **Relationship** to show only the entities connected to Store.

![Store relationships in the Retail Ontology](../assets/screenshots/ontology-store-context.png)

*The Relationship view shows Store connected to Geography, Receipt, Promotion,
and the machine-learning StockoutRisk entity.*

The ontology maps business concepts to existing Lakehouse and Eventhouse data.
It does not replace the physical schema or copy the source data.

## 2. Test a grounded data-agent answer

If the semantic-model agent passed its source and permission checks:

1. Open the **Agents** folder.
2. Open `retail-semantic-model-agent`.
3. Select **Test data agent**.
4. Ask for net sales and gross margin for a complete month, for example:
   *"What were total net sales and gross margin % for September 2026? Name
   the measures used."*

![Semantic-model data-agent response](../assets/screenshots/data-agent-semantic-model.png)

*The data agent answers from the `Net Sales` and `Gross Margin %` measures and
states the date range, so the result can be checked against the report.*

The agent can use every table in `retail_model`, including the receipt-level
fact tables. Ask about a complete month: the latest month is usually partial,
so month-over-month and year-over-year figures for it look artificially low.
If you compare with the report, set the report's date filter to the same month
first. Check each generated answer against
measures, query output, and source timestamps.

Skip an agent when it has no selected data sources, returns an error, or has
not passed its capability and access checks. The ontology graph can still be
shown independently when its bindings are valid.

## 3. Close with the Power BI outcome

1. Open the **Reports** folder.
2. Open the `retail_model` report.
3. Start on **Executive Cockpit**.
4. Continue to **Sales**, **Supply Chain Control Tower**, **Omnichannel
   Fulfillment**, or **Operations & Marketing** when the audience wants more
   detail.

![Power BI Executive Cockpit](../assets/screenshots/power-bi-executive-cockpit.png)

*The Executive Cockpit combines omnichannel performance, store comparisons,
ML risk signals, and an AI-generated narrative over the Direct Lake semantic
model.*

Direct Lake is the Power BI connection mode that reads Lakehouse tables
directly without importing another data copy. The report opens on the latest
month generated by this deployment, not a hard-coded month shared by every
workspace.

State the selected data period before discussing a value. All values are
synthetic, and an AI-generated narrative can contain inaccuracies. Use the
underlying measures and source timestamps as evidence.

## 4. Optional full-demo extensions

Show these surfaces only when deployment and readiness confirmed them in the
target workspace.

| Surface | Where to find it | What to say |
| --- | --- | --- |
| Connected operational twins | `retail-twins` report in the **Reports** folder | A separate report over the same governed data; it is not a page of `retail_model`. |
| Post-Reporting extended ML | `ml-optional` and `ml-experimental` pipelines | Journey analysis (`journey_patterns`), delivery prediction (`dwell_predictions`), and experimental dynamic pricing (`pricing_recommendations`) run after Reporting and are not Reporting prerequisites. |
| Replenishment case preparation | `prepare-replenishment-case` notebook | Prepares a human-reviewed replenishment draft from availability signals derived from required ML outputs. |
| Retail Operations Fabric Apps | `retail-merchandising`, `retail-promotions`, and `retail-approvals` in the **Fabric Apps** folder | Three standalone apps for separate business functions. The merchandising portal shows item trends, in-stock rate, and days of cover over a synthetic sample catalog. The promotion studio models discount and break-even what-ifs. In replenishment approvals, a different reviewer records append-only decisions on proposals. The apps do not change prices, place orders, or execute transfers. |

## Connect from VS Code (MCP)

The Data Agent and Ontology expose streamable-HTTP Model Context Protocol
(MCP) servers. Call them from Copilot's agent-mode chat in VS Code to test
questions before connecting them to the
[agentic application](../design/architecture/agentic-application.md).
Each call is a JSON-RPC `POST` authenticated with a Fabric bearer token.

The endpoint URLs follow these shapes (substitute your workspace, data-agent, and
ontology-item GUIDs):

```text
# Data Agent (semantic model)
https://api.fabric.microsoft.com/v1/mcp/workspaces/{workspaceId}/dataagents/{dataAgentId}/agent

# Ontology (business graph)
https://api.fabric.microsoft.com/v1/mcp/dataPlane/workspaces/{workspaceId}/items/{ontologyItemId}/ontologyEndpoint
```

**1. Sign in** to the tenant that owns the workspace:

```powershell
az login
```

**2. Obtain a Fabric token** and copy the output. Tokens are valid for about
60-75 minutes:

```powershell
az account get-access-token --resource https://api.fabric.microsoft.com --query accessToken -o tsv
```

**3. Add `.vscode/mcp.json`** (the `.vscode/` folder is gitignored). VS Code prompts
for the token once per session and passes it in the `Authorization` header:

```json
{
  "inputs": [
    {
      "type": "promptString",
      "id": "fabric-token",
      "description": "Fabric bearer token (az account get-access-token --resource https://api.fabric.microsoft.com --query accessToken -o tsv)",
      "password": true
    }
  ],
  "servers": {
    "retail-data-agent": {
      "type": "http",
      "url": "https://api.fabric.microsoft.com/v1/mcp/workspaces/{workspaceId}/dataagents/{dataAgentId}/agent",
      "headers": { "Authorization": "Bearer ${input:fabric-token}" }
    },
    "retail-ontology": {
      "type": "http",
      "url": "https://api.fabric.microsoft.com/v1/mcp/dataPlane/workspaces/{workspaceId}/items/{ontologyItemId}/ontologyEndpoint",
      "headers": { "Authorization": "Bearer ${input:fabric-token}" }
    }
  }
}
```

**4. Start the servers.** Select **Start** above each server in `.vscode/mcp.json`,
or run **MCP: List Servers** from the Command Palette. Paste the token, then
open Copilot Chat in **Agent** mode and confirm both tools are enabled.

The Data Agent advertises one tool (`DataAgent_<name>`); the Ontology advertises
`list_ontology_entity_types` and `search_ontology`. If calls return **401**
because the token expired, repeat step 2, then use **MCP: List Servers** to
restart the servers.

!!! tip "Which one to ask"

    Use the Data Agent for aggregates, rankings, and trends, such as the top
    10 products by revenue last quarter. Use the Ontology for a named
    entity's related data, such as a loyalty member's segment and churn
    probability. Deep multi-hop scans can fail.
